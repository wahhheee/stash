# 阶段五：开关与记忆页

日期：2026-11-16。宿主保持 0.2.2-rc.3。

## 请求边界

宿主先解析工具集合并组装提示，再运行 agent/pre-step。因而在 pre-step 补注册会使首次开启晚一轮。实现采用 agent 作用域注册和 tools.register 的 when 条件：首次关闭时工具集合不含 stash，说明为空；首次获准后，当前 agent 的声明保持到生命周期结束，全局关闭除外。工具执行仍逐次校验最新权限。该生命周期标记只控制声明，不代替 surface 中的常驻状态。标准与 PTC 的全局初始关闭均通过请求逐字节比较。

开关通知作为版本化常驻记录；关闭记录不包含此前正文。重新开启、只读变化和继承变化均生成完整快照，以保证压缩与重启后语义明确。干净模式仍提示用户明确要求时可以读写工作区，程序不猜测用户自然语言是否授权。

## 持久化

全局 enabled 使用宿主配置与重载机制。工作区设置保存在 workspace.json 的可选 switches 字段，会话设置使用宿主 stash_switches 存储域（域版本 1、记录 v: 1）。未知版本明确失败。工作区元信息刷新保留设置；工作区设置和内容写入共用锁。设置不进入 Markdown 内容修改链，历史请求的实际策略保存在无正文决策记录中供重放。

分叉在 agent 创建时复制设置。设置复制使用切口事件指纹匹配，而不是最后一次记忆载体的会话 ID；后者可能属于更早的祖先。多个候选设置一致可复制，不一致则明确拒绝，不猜测隐私设置。旧日志没有设置时按默认值处理。

## 人工编辑

界面与模型复用路径、frontmatter、预算和凭据校验。人工保存携带加载时的内容哈希；独立编辑实例不向模型授予完整读取资格。只读开关限制模型，人工编辑仍可使用。会话编辑通过宿主 runMaintenance 避免与工具写入交错，提交进入原始日志后显式调用 sessions.flush；忙碌时明确失败并保留草稿。读取页面与修改开关不激活冷会话。

宿主要求第一条可见消息是其受保护的 system/message，且 user/message 必须携带 surfaceOp；空白会话先追加编辑通知会生成不可重放的日志。实验性 plugin record 不适合作为本阶段正式记忆正本。因此会话记忆编辑在首次请求建立系统消息后开放；首请求前所有开关与工作区编辑均可用。界面明确展示此限制。

批量清空检查整份加载快照的哈希。工作区清空持锁逐项写入可恢复删除日志；故障可导致部分删除，下次访问恢复当前 pending，用户刷新后可再次清空。不宣称跨文件原子删除。会话清空追加删除提交，既有分叉、工作区内容及原始对话不变。两者均保留历史副本，二次确认说明范围，不提供安全擦除承诺。

## 界面与发现

右侧栏提供设置、规则与笔记编辑、创建、删除、提升副本和清空。输入框工具行提供会话四项设置。工作区菜单经宿主 openWorkspace 进入该工作区，再打开 stash 页。全局硬闸的可写入口是宿主插件配置；记忆页展示全局来源并禁用下级开关。

隐私设置隐藏普通清单、搜索和短路径访问；完整 dsh:// 引用继续作为明确访问入口。每次历史调用重新检查隐私状态，设置变化使已有分页快照失效。页面通过本客户端事件和连接重置刷新，也提供手动刷新；正在编辑的草稿保留并提示重新加载，保存时版本检查仍是最终边界。
