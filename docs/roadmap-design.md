# 设计方向

stash 希望让持续性要求跨会话生效，让经验在原有条件下复用，并让历史结论可以回到原话核对。[工程设计](design.md) 说明实现与存储契约。

## 记忆的内容

项目文件能够直接表达的约束，优先写在负责该行为的代码或文档里。需要模型持续遵守的要求写成规则，有条件的结论、背景和经验放在笔记里。一次讨论的证据保留在会话日志中，笔记可以用来源引用连接原文。

规则与笔记中的长期做法直接写当前事实、条件及原因。修改时原地重写，变更经过由会话日志和修改日志承担。经验笔记可以回顾当时发生的事件，供以后复用的部分要写清适用条件。这个区分同样适用于工程文档与提交记录。

## 后续扩展的边界

- **按路径生效的规则**需要定义匹配的工作区路径、继承关系和预算。规则展开与适用范围由领域层负责。
- **历史全文索引**可以从原始事件派生。检索结果需要保留分叉去重、可发现性与精确事件范围，且索引应能从原始记录重建。
- **其他会话提交载体**需要与历史日志共同折叠，按同一提交身份去重。会话的分叉切点和离线重放应得到相同的结果。
