# 0002：工作区记忆的持久性与重放

日期：2026-11-13。状态：已实施，0.2.1 收尾调整见下文。

阶段二沿用工作区 Markdown 正本和可见上下文比对。宿主源码与真实 SDK 已确认：外部包可声明消息来源、tokenMeter 可估算、作用域提示和工具可注册、pre-step 来源化消息会持久化、压缩 checkpoint 携带被替换事件的范围。

## 0.2.0 初始调整

- 不以 mtime 作为内容未变的保证。当前规模每次请求直接扫描并计算哈希，避免编辑器保持时间戳而漏报；性能缓存留待规模测试提供依据。
- .journal.jsonl 保持逻辑只追加，物理使用整个文件的原子替换；.pending.json 保存可恢复操作。这样避免文件成功而修改历史缺失，以及 JSONL 尾部撕裂。代价是日志变大后写放大；32 MiB 单文件上限会明确拒绝，未实现轮转。
- 规则增量用连续行替换范围表示，重复行和删除也能明确表达。小改动不重发整份规则。
- 成功写入结果包含当前有效规则。否则，一次写入前发现了外部编辑，隐藏 meta 却确认整份新规则，会把模型没看到的外部内容误当成已知。以明确正文换取确认状态的一致性，暂不优化这部分 token。
- trace 默认关闭仍需精确重放，所以新增不含正文的版本化决策旁车；它引用修改日志 ID，避免依赖时间戳推测跨进程顺序。报告包不自动收集这些文件。
- 不抢占疑似过期锁，避免暂停进程、PID 复用或共享目录误判导致双写。doctor 检出，人工确认所有访问进程停止后清理锁，再由 pending 恢复。
- 不承诺尚未实现的历史工具。压缩范围行只说明范围与当前快照的作用。
- 显式锁定 zod 4.4.3：新增宿主依赖解析时拉入不同次版本，导致 Typert Zod 类型不兼容；本阶段维持原有依赖基线。

## 0.2.1 收尾调整

讨论后决定降低正常请求的持续成本。子代理只读，不以高并发多写者系统作为当前优化目标；保留先读后改、短时排他锁、原子替换和最小中断恢复。这些保护仍覆盖用户手改及单进程中断。

- 用 mtimeMs 与文件大小作为缓存入口，只对首次或变化的文件读取正文和计算哈希。接受保留相同时间与大小的外部修改可能漏检；显式读取和写前目标版本检查仍绕过缓存。修改日志也缓存已验证的记录和最新状态，元数据变化或明确诊断时完整校验。
- .journal.jsonl 改为打开追加句柄、写入一行、sync 后关闭。保留 .pending.json，只有有效前缀之后的残片能与 pending 的原始字节对应才修复，避免把无关损坏当作中断；完整日志不重复追加。为外部编辑记日志也使用 pending。
- .decisions-* 按本轮约定继续整体原子替换，不扩展其格式和恢复协议。它的读写成本仍随历史增长，当前作为明确保留项，不声称所有日志都已完成追加优化。
- 工具结果只保留路径、预算和 replace 删除行；在 v: 1 写入记录增加可选 trusted 字段，旧记录缺省沿用原语义。仅当写前规则与会话可见规则一致时确认新状态，不把已经被别的读操作或会话记录的外部修改漏掉。允许交错时下一请求的差异包含本次自己的改动，避免实现多方变更合并。
- 新引入的规则引用没有在调用参数里展示正文，嵌套调用也不保证参数对模型可见，因此都保守补发。规则增量与压缩恢复沿用现有模板与配置。
- 写入及追加容量在变更前检查，避免写出超过读取上限的文件。没有增加日志轮转、自动抢锁或多会话调度；阶段二仍不含会话记忆与历史检索。

## 验证与限制

本地 Windows 自动化覆盖核心规则与索引、mtime 缓存与写前绕过、UTF-8 残片恢复、损坏日志和恢复冲突、两个独立 Node 进程并发、Cordis 生命周期、真实 SDK 简短写入结果和请求期间外部编辑、重启与压缩、Web Gateway、tarball 安装，以及这些会话的离线 reconcile。普通测试只连接本地 mock。

行为评估框架包含持续规则、局部例外、仅凭索引回答和笔记描述结论四个任务，支持重复执行、语义判定证据与 token 汇总。仅验证框架，不把脚本通过率当真实模型行为成绩。真实模型评估、Linux/macOS CI 和阶段二 Desktop 人工视觉检查尚未在本地执行。
