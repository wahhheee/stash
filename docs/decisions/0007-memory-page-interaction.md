# 记忆页交互与结构化编辑

日期：2026-11-17。宿主保持 0.2.2-rc.3。

## 问题与范围

原页面把设置、文件选择、路径与全文编辑堆在一起。“新建笔记”实际初始化草稿，“保存”缺少操作范围，初始化的空 description 又不能通过笔记校验。用户必须理解 YAML 与虚拟路径，失败后也没有清楚的读回和恢复流程。原生下拉选项在宿主深色主题下出现白底浅字。

本次调整保持已有持久格式和读写边界，重新组织用户任务。顶部范围控制三个分区；分区分别管理笔记、规则和设置，而非彼此拥有隐含的范围。侧栏使用列表、详情、编辑的逐层导航，避免在窄栏里并排挤压。

## 元信息与位置

不要求用户手写 YAML，但保留显式元信息编辑。type、description、sources、index、status 使用选择和输入控件。正文不承载隐藏的表单字段。未知字段保留，复杂 sources 无法无损投影时只读展示。编辑会重新序列化 YAML，保留字段语义，不承诺保留注释、锚点和排版。

description 同时表达简短主题或用途和关键结论，避免重复。英文 INSTRUCTIONS 与 GUIDE 在原工程基础上修改，不另建并行的中文模型提示，不解析连接符，也不增加内容重复的标题字段。正文补充条件、例外、理由和证据；sources 保存依据材料，正文仍可有链接和摘录。

位置使用目录建议、子目录草稿和文件名，另提供直接路径输入。这个选择保留了子目录能力，又无需先掌握记忆的内部路径格式。新建与复制提供位置选择，已有笔记位置只读；移动与重命名需要另外处理规则引用和来源，不纳入此次修改。

## 保存、冲突与草稿

写入成功和读回失败是不同结果。mutateMemory 返回文件与版本回执，客户端先显示已保存内容，再刷新完整列表。请求 ID 只在当前宿主实例的有界缓存中去重；持久层仍以版本与目标存在性保护数据，不宣称跨重启的永久幂等。

失败分为字段校验、目标已存在、版本冲突、会话忙碌、预算、凭据和连接错误。冲突展示最新内容，用户核对后决定丢弃草稿或以最新版本继续编辑，保存时继续做版本检查，不静默覆盖。固定页脚预留反馈空间，避免短错误提示改变编辑区域高度。

页内切换有保存、放弃、继续编辑三个明确选择。宿主会话切换无法靠页面弹窗阻止，因此草稿按工作区或会话保存在插件实例内，重新进入时恢复，不写入浏览器持久存储。插件卸载或浏览器刷新清除草稿。首次请求前会话编辑仍受宿主受保护系统节点约束，提前说明并禁用创建；工作区编辑和开关继续可用。

## 组件、构建与验证

按钮、菜单、开关、输入、分段标签和对话框复用当前安装的宿主 primitives，使用同一主题变量。官方 Markdown 源组件依赖较多仅列在宿主开发依赖中的包；此处使用内联的 react-markdown 与 remark-gfm 渲染正文，关闭 HTML，使用宿主颜色和间距。没有为此扩张宿主运行依赖。

tsdown 的 CJS 输出默认把解析平台切回 Node。classic 包装仍须使用浏览器解析条件，因此通过 inputOptions 明确覆盖 platform，产物外部依赖仅 React、react-dom 和 JSX runtime；工厂加载测试在 DOM 环境中执行。

验证包含结构化元信息保留、重复提交、真实 Gateway 往返、界面任务流程、冲突恢复和草稿恢复。隔离 DSH_HOME 的真实 Web 配合本地 mock，在 Edge 中检查浅深色、360/600/900 像素宽度、菜单键盘操作、创建读回、会话规则、复制、删除及冲突。该验证不代表真实模型的索引质量评估。
