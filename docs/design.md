# stash 0.6.0 工程设计

stash 是 DSH 外部插件，提供工作区与会话规则及笔记、分叉继承、常驻上下文、原始历史查询与引用、三级开关、记忆编辑页、诊断、增长指标、按计划整理与整组回滚，以及离线重放。长期设计见 [目标设计](roadmap-design.md)。

## 分层

core 包含宿主无关端口、工作区路径校验、YAML frontmatter、规则展开、索引折叠、可见状态折叠和全部模型模板。YAML 解析使用 yaml；未知字段和类型保留。plugin/adapters 负责宿主协议、配置、文件系统和持久格式；host 编排读写；core 计算继承开关，adapters 负责宿主策略与设置持久化；client 提供记忆页和输入框控件。devtools 提供离线只读检查、重放与测试夹具。只有 plugin 发布，core 和 yaml 内联进产物。

## 工作区存储

工作区以 DSH WorkspaceId 标识，在 memoryRoot/<WorkspaceId>/ 保存 workspace.json、RULES.md、notes/**/*.md、.journal.jsonl。workspace.json 的 format 为 1，记录 ID、最后已知路径和标题。工作区通过宿主注册表中的会话归属或 cwd 解析；不存在时注册该 cwd。没有 cwd 的会话明确失败。

每次请求扫描文件清单并检查 mtimeMs 与大小；首次观察、新文件和元数据变化时才重新读取正文并计算 SHA-256。缓存按工作区保存在当前进程中，包含路径、时间、大小、内容与 revision；删除和插件自己的写入会失效对应项，重启后重新建立。显式读取与写前目标文件校验绕过缓存。保持相同时间和大小的外部编辑可能暂时漏检；尚未观察到的外部中间版本不保证保留。

每条修改日志 v: 1，包含 ID、时间、工作区、路径、操作、会话与调用 ID、修改前后全文和哈希。日志首次加载或元数据变化时完整解析并验证链条；未变化时复用已验证的记录、最新文件状态和 ID 集合。插件成功追加后直接更新该缓存。公开 journal 读取、doctor 和 reconcile 强制检查完整历史；未知版本、损坏链和未知 workspace 格式拒绝处理。

工作区 .lock 采用排他创建，等待上限 5 秒。临界区覆盖元数据扫描、规则预算、哈希比较、文件替换和日志提交。写入先落 .pending.json，再用临时文件加 rename 替换记忆文件，随后向 .journal.jsonl 追加一条 JSON 加换行、sync 并关闭，最后删除 pending。外部编辑的日志追加也先保存 pending。记忆文件与 pending 先 sync，再 rename；修改日志不整体重写。

pending 在下次请求恢复。恢复校验当前文件必须匹配 before 或 after；只有完整前缀有效、末尾未完成记录的原始字节与 pending 对应时才截去残片并补齐。已记录的同 ID、同内容操作不重复追加。没有 pending、无关残片、中间损坏、未知版本或链条不符均报错。完整有效但没有末尾换行的旧日志可读取，下一次追加补上分隔符。

残留锁不会自动抢占，需确认进程已停止后人工清理。多个写入按锁串行处理，基于旧版本的覆盖返回 STASH_STALE_READ；不做自动合并或跨会话调度。本地文件系统是当前支持场景，不声称网络文件系统或断电下的完整事务保证。

路径拒绝父目录、反斜杠、百分号、控制字符、Windows 保留名和大小写冲突。目录链接与非普通记忆文件拒绝读取，单文件上限 32 MiB；写入与日志追加也检查大小，修改日志容量不足在替换记忆文件前拒绝。显式单文件读取不持有工作区锁；插件间写入有锁，外部编辑器不遵守该锁。

## 规则与笔记

/RULES.md 的正文作为规则；注入时去掉 src 来源注释，文件读取保留。独立成行的 @notes/name.md 并入笔记正文，只展开一层。规则 frontmatter 含 paths 时拒绝。规则预算含全部展开内容；工具写入或外部规则超预算时明确失败，不截断。

笔记 frontmatter 必须包含单行 type 和 description；index: false、status: archived 退出索引。archive 保留未知字段但会重排 YAML 格式。description 将简短主题或用途与最重要的事实、结论或经验及关键条件结合，减少重复，使索引本身提供主要信息；分隔符不参与解析。这是提示指导，不做自然语言自动判定。

索引按路径稳定排序，超预算依次折叠篇数最多的子目录、根目录笔记类型、剩余目录。折叠目录使用 README.md 的描述；最终保留展开入口与省略组数。

memory_view 支持 /、/RULES.md、/notes/ 及子目录、笔记文件、/.guide.md。长结果按预算分页，cursor 绑定当前 agent、路径、内容哈希与连续读取进度。完整读取后才获得 edit、replace、archive、delete 的修改资格。工具写入不自动授予下次覆盖资格。

memory_write 支持 create、append、edit、replace、archive、delete。create 要求不存在；append 在锁内追加且要求文件存在；edit 要求旧文本唯一；replace 返回被删除的行。规则不可 archive/delete，清空须读取后 replace。子代理默认只读，可用 subagentWrite 放开。常见 API key、Bearer、GitHub token、AWS access key 和私钥头拒绝存储；外部扫描在写入日志前检查，不把匹配正文放入错误。此检查不替代用户的隐私判断。

六种操作共用 path 和 op；create、append、replace 必须提供字符串 content，edit 必须提供非空 old 和字符串 new，new 为空字符串表示删除匹配文本。archive、delete 只接受 path 和 op；其余正文参数必须省略，空字符串和 null 均不等于省略。操作字段表同时生成工具说明、输入类型和适配器校验规则。STASH_INVALID_DATA 按参数缺失、类型、多余字段、编辑零匹配或多匹配、笔记 frontmatter 格式给出具体修正提示，不回显输入正文和底层异常。

工具错误采用错误码加结构化原因，在 core/templates 中生成完整说明。STASH_READ_ONLY 区分当前子代理无写权限、其他会话记忆只读和历史只读；STASH_ALREADY_EXISTS 表示 create 目标已存在，读取后需选择更新操作或另一个路径。STASH_STALE_READ 按写前版本、续读游标和 pending 恢复冲突分别提示；读取预算与规则预算分别说明。模型可见错误不直接拼接底层异常正文。归档回执说明文件仍保留、后续索引排除且既有规则引用仍生效；删除回执明确目标已删除，两者不附加笔记提升提示。

## 常驻上下文

静态说明和两个工具按 agent 作用域注册，与具体工作区和会话无关。agent/pre-step 在宿主放行请求后读取当前记忆，按 session.surface 的可见顺序折叠完整快照、规则增量与仍可见的成功写入结果。来源类型 stash-memory，元数据 stash.v 为 1，存储所表达的结构化状态。

没有完整快照时注入完整上下文；规则一致时不注入；仅索引变化延后；外部规则变化按连续行差异追加通知；通知超过规则预算一半时改用完整快照。工具成功结果正文只含路径、规则预算和 replace 删除的行，不重发完整规则。原生调用使用结果 meta，嵌套调用同时使用 deferContext。

写入记录仍使用 v: 1，新增可选 trusted 字段；没有该字段的旧记录保持原有确认语义。只有写前实际规则与会话可见规则一致，才确认普通自身写入后的状态；trusted: false 的写入不推进可见规则。外部编辑即使已经被别的操作记入日志，仍由这个比较识别；下一请求按配置补发差异，允许同时包含刚写过的部分。新引入的规则引用和嵌套工具调用按不可信记录处理，避免把未展示的引用正文或嵌套参数当作已知。

压缩删除快照后，最新完整快照重新进入上下文，包含宿主 checkpoint 的源事件范围。范围行提供 ./log/<a>..<b> 原文读取提示。记忆中的尖括号在注入时转义，避免提前闭合模板。

全局 enabled 是硬总闸，工作区与会话三态设置取最近明确值。宿主工具启用条件在提示组装前计算，初始关闭时不向模型暴露工具与说明；同一 agent 开启后保留声明，执行时再校验。关闭通知与模式变化使用完整常驻记录，重新开启恢复完整快照。干净模式跳过工作区规则和索引，保留会话层。externalRuleUpdates 可选择下次请求或下次完整恢复时生效。无独立私有“已发送”缓存作为事实来源。

## 会话记忆与分支

会话层不落独立 Markdown 文件。每次写入产生 v: 1 提交，包含 UUID、写入时会话 ID、路径、结果全文或 null、修改前后 SHA-256。原生调用保存在成功 tool/result 的 meta.stashCommit；PTC 嵌套调用通过 deferContext 追加 stash-commit 来源消息。失败工具结果不作为提交；通知载体也供后续界面编辑使用。界面编辑复用通知载体，在首次请求建立受保护系统节点后开放；空白会话仍可编辑工作区与开关。

stashSessionMemory 是 stateVersion: 1 的宿主投影，按原始事件顺序折叠提交，验证版本、哈希、路径、凭据与修改前版本。相同提交 ID 和内容指纹幂等，冲突 ID 与断链明确失败。宿主裁剪产生的重复结果不重复应用；压缩移除可见消息不会移除原始提交。缓存由宿主维护，可以删除并从原始日志重建。

同一次根调用中的嵌套读写可观察尚待外层结算的提交。最终工具失败撤销对应的待提交项，根调用结算或新请求清空暂存；持久状态只从最终日志重建。外层调用失败时是否已写入，以宿主最终留下的提交通知为准；不存在插件私有的成功副本。写入沿用工作区的六种操作、完整读取资格、旧版本检查、frontmatter、规则预算与凭据校验，单次结果文件上限 32 MiB。

./RULES.md、./notes/ 和 ./ 是当前会话。../<id>/、/sessions/<id>/RULES.md、/sessions/<id>/notes/ 只读同工作区会话；完整 dsh://session/<id>/RULES.md 或 /notes/<name>.md 引用可跨工作区只读。其他会话的内容用 reference-only 包装，不授予本会话写入资格或成为常驻规则。

跨会话目录条目使用包含完整会话 ID 的 dsh:// 引用，可直接作为下一次读取路径。笔记写入回执说明会话作用域与显式检索能力，索引显示仍受 index/status 元数据及刷新时机影响；笔记搜索结果明确是所选会话的当前存储版本，而非时间窗内的历史快照。

常驻快照含工作区规则及索引、会话位置、会话规则及索引。工作区和会话层分别使用 rulesBudgetTokens、indexBudgetTokens。优先级为用户直接指令、仓库指令、会话规则、工作区规则。会话笔记索引只列本会话折叠结果，索引变化仍延迟到完整快照刷新。自身成功写入只确认对应层；PTC 记录保守补发会话规则。

分叉完全依据宿主复制的原始前缀，继承切点之前的会话记忆，之后互不影响。继承快照仍可见、规则未变时只追加位置通知，不重写前缀。没有可见快照时完整恢复。谱系展示先取继承前缀中最后的 stash 提交或常驻记录的会话 ID；没有记录时用切口事件完整指纹匹配同工作区会话，多个候选保留歧义。谱系不参与状态继承。

子代理默认只读，并在快照中单列父会话当前规则。父规则变更在下一请求刷新。subagentWrite 放开后，子代理可写工作区和自己的会话；不会直接写父会话。决策旁车只记录父会话 ID 与读取边界，重放需要相应父日志，不保存父规则正文。

/sessions 显示规则非空行数、笔记文件数和可推断谱系；query 另外扫描满足时间窗的会话当前笔记全文。笔记结果指向当前文件，不声称是时间窗内的历史版本。提升通过读取会话笔记再 create 工作区笔记实现，sources 由调用方指回原会话，原文件不变。会话笔记写入结果提醒其作用域和提升方式。

## 原始记录与引用

memory_view 支持 /sessions、/sessions/<id>/log/turns、log/summaries、log/<seq>、log/<a>..<b> 和 ./log。完整 dsh://session/<id> 引用可带事件或事件范围；dsh-session: 解码为会话引用。工作区内的短 ID 去掉 session- 前缀，从至少八个字符扩展至唯一；歧义报错并返回候选。普通路径通过 WorkspaceId 的 sessionIds 限定范围，完整引用可只读访问其他工作区。发现策略按会话 discoverable 过滤普通路径、清单与搜索；当前会话与完整引用不受过滤。设置变化使历史分页快照失效。

宿主适配器通过 sessionQuery 的只读观察与同步 inspectSession 读取活动或持久会话，不恢复 agent、不写原始日志。stashHistory 是 stateVersion: 1 的宿主投影，记录轮次起止 seq、时间、首个用户文本预览和最后助手文本预览；宿主 projection cache 保存并验证检查点。单个事件引用展开所属完整轮次；范围引用严格保留边界，缺失边界明确失败。brief 省略推理并折叠长事件，full 返回完整事件 JSON；两者均脱敏已识别的凭据。压缩摘要由 isCompactCheckpointSource 识别，输出原始 sourceEventSeqs。

query 仅用于历史路径。匹配基于宿主 extractSessionEventText 生成的语义文本，忽略大小写、连续空白归一化，支持两字中文词。搜索一个会话不需另加时间窗；搜索 /sessions 须有 since/until 或 all: true。时间必须是带时区的 ISO 8601，边界包含在内；本地“昨晚”等日历范围由调用方换算。清单按创建时间或任一事件时间判断是否在窗口内，轮次按时间区间是否相交筛选。当前实现顺序读取候选会话全部日志再筛选，时间窗减少结果范围，不承诺减少磁盘读取量。

搜索结果按事件时间排序，含完整引用、事件类型、时间、命中附近片段、查询、扫描会话数与截断状态。同一原始事件的继承副本按事件全文指纹合并并注明其他分叉；独立同文事件不合并。零结果标记 no-match；搜索范围读取失败为 STASH_SEARCH_FAILED，浏览目标不可读为 STASH_HISTORY_UNREADABLE，不以空结果代替失败。

历史结果用 memory-history 包裹，尖括号转义并声明仅作参考。结果不进入常驻规则。长结果按 viewBudgetTokens 分页；每个 agent 最多保留八个续读快照，cursor 绑定完整参数和偏移。续读读取固定快照，当前会话新增工具结果不会使其失效；改变参数、重启或快照被淘汰时须重新读取。历史读取不授予记忆写入资格。

客户端每轮助手回复提供“复制本轮引用”图标按钮，使用宿主会话引用图标、主题变量和 Tooltip，尺寸跟随内容字号。提示说明粘贴后可让模型定位并读取本轮原始记录；获取期间阻止重复操作，成功显示勾号两秒后恢复，失败显示重试提示。状态同时提供无障碍播报，反馈不改变操作栏布局。宿主 getReference 按消息 ID 定位已完成轮次，返回完整 ID、标题、轮次、范围和 UTC 时间。会话菜单 order: 460 提供“复制会话引用”。链接文字跟随界面语言，标题转义 Markdown。宿主接口只返回定位数据，复制动作不注入历史正文。客户端样式内联到 classic script，由插件作用域安装和释放。

离线 view 可附 sessions 目录、当前会话 ID 和查询选项 JSON，使用宿主 read 句柄和同一模板完成分页。离线目录没有工作区注册表，清单按 workspace.json 中最后已知路径与日志 cwd 精确相等筛选，路径改名后的成员应通过完整引用读取。离线操作不写投影缓存。

## 开关存储与记忆页

工作区设置是 workspace.json 的可选 switches（v: 1），与文件写入共用锁并原子替换，元信息刷新保留设置。会话设置使用宿主 stash_switches 域（版本 1）按 ID 持久化；分叉按切口事件指纹推断源并复制，一致的多候选可复制，不一致明确失败。开关不进入内容修改链，决策记录保存生效策略以支持离线重放。

右侧栏默认打开本会话笔记。顶部范围选择同时决定笔记、规则和设置的作用范围，显示会话或工作区名称；工作区菜单通过导航参数直达对应工作区的整理或设置页。笔记使用目录分组列表、只读详情与独立编辑表单，显示计数、类型、归档和索引状态。新建只打开表单，创建成功后展示保存内容；已有笔记编辑使用“保存修改”，规则独立使用“保存规则”，设置即时保存。输入框使用宿主菜单提供会话四项设置和记忆页入口。全局硬闸通过宿主插件配置修改。中英文文案跟随宿主。

表单显式编辑 type、description、正文、sources、index 和 status。自定义类型和状态保持原值；不受表单管理的元信息通过解析合并保留。字符串和字符串数组来源投影为可编辑条目，可选显示名称编码为 Markdown 链接；结构化来源只读展示并保留原值。正文使用禁用 HTML 的 Markdown/GFM 渲染；会话引用打开对应会话，来源引用另可复制。来源与正文内链接、摘录各自保存。无法投影的笔记保留原文展示，不伪装为空笔记。

新建与复制的保存位置支持目录建议、子目录草稿、文件名和直接输入路径。路径显式区分工作区 /notes/ 与会话 ./notes/；相对位置以当前范围为准。文件名自动补全 .md，预选名称避开已有文件，保存前及宿主写入时检查冲突。已有笔记位置只读；不提供移动或重命名。复制到工作区保留原笔记并加入来源引用。

页面读取使用只读历史观察，不恢复冷会话。人工保存校验用户加载时的 SHA-256，独立编辑实例不授予模型读后改资格；所有路径、格式、凭据和预算校验复用原实现。会话修改在宿主维护时段执行，追加提交通知后显式 flush；活动请求期间拒绝修改并保留草稿。

mutateMemory 返回独立写入回执或结构化错误；成功后客户端先更新已保存内容，再读取列表。刷新失败不改写保存结果。相同目标、请求 ID 和动作复用宿主当前实例中的回执缓存（至多 256 项），不同动作复用 ID 被拒绝；失败可重试，宿主重启后仍依靠路径唯一性和版本检查防止静默覆盖。旧 changeMemory 接口保留。

清空检查整个加载快照哈希，工作区持锁逐项追加可恢复删除记录，会话追加删除提交。两者均保留设置、修改历史与原始对话，既有分叉不变。工作区批量删除不具备跨文件原子性，故障后刷新可见已完成部分。界面二次确认说明范围。

本客户端修改和连接重置触发刷新，外部修改可在记忆页手动刷新；输入框快捷菜单仅在状态读取失败时提供“重试”。草稿不被刷新覆盖。冲突对话展示最新保存内容，允许放弃草稿或保留草稿并更新比较基准；再次保存仍检查版本。页内离开提供保存、放弃与继续编辑。草稿按工作区或会话保存在插件实例内，外部切换会话或重新打开侧栏可恢复；插件或浏览器重载不保留。操作反馈和保存动作位于固定页脚，字段错误显示在对应输入旁。控件复用宿主按钮、菜单、开关、分段标签和对话框，样式使用宿主主题变量。具体取舍见[阶段五决策](decisions/0005-switches-memory-page.md)与[交互重构决策](decisions/0007-memory-page-interaction.md)。

## 配置

| 配置                | 默认            | 说明                                       |
| ------------------- | --------------- | ------------------------------------------ |
| enabled             | true            | 全局记忆开关，宿主配置重载生效             |
| subagentWrite       | false           | 放开子代理写入工作区与自身会话             |
| memoryRoot          | DSH_HOME/memory | 绝对路径、相对 DSH_HOME 或 ~               |
| rulesBudgetTokens   | 1600            | 128–32000，每层展开后的规则预算            |
| indexBudgetTokens   | 1600            | 128–32000，每层索引预算                    |
| unreadDays          | 90              | 1–3650，长期未读天数                       |
| maintenanceModel    | 空              | 整理会话沿用发起方的提供商；空值沿用原模型 |
| viewBudgetTokens    | 4000            | 256–64000，单次读取预算                    |
| externalRuleUpdates | next-request    | next-request / next-compaction             |
| trace               | off             | off / metadata / content                   |
| traceRetentionDays  | 7               | 1–365 个 UTC 日历日                        |

配置经 Schemastery 校验，变更由宿主重载生效。预算通过 ctx.tokenMeter.estimateMessage 扣除固定消息包装估算；锁定 DSH 的算法为每 4 个 UTF-16 码元约 1 token，并非模型精确分词。devtools 使用同一算法；离线 render 的预算使用默认值。

## 诊断与重放

/stash status 显示版本、记忆目录、预算与生效开关及来源；context 比较工作区、会话层的可见与实际版本；render 输出现在完整注入的文本；explain [1–100] 显示当前实例最近的决策及哈希。doctor 检查权限、格式、修改链、文件一致性、锁和待提交记录。

每个工作区保存 .decisions-<SessionId>.jsonl，每行 v: 1，仅包含请求前日志位置、修改日志版本 ID、配置、决策、正文哈希和压缩范围，没有正文。它独立于可关闭的 trace，用于精确离线重放；当前不自动清理。决策文件继续采用整体原子替换，每次写入校验已有记录；当前没有为它提供残缺尾部恢复。reconcile 用 DSH persistence 的 read 句柄读取日志，以 Session 重建各请求前的 surface，并从修改日志版本重建实际记忆，比较决策和实际注入文本。未发出模型请求的尝试单独标注。重放需要完整会话日志、工作区修改日志与决策记录；子代理还需其引用的父会话日志。阶段四决策含 sessionMemory 标志，兼容没有该字段的旧工作区决策。离线 fold 按提交输出每一步的文件状态。

trace 按 UTC 日轮转；报告为 format: 1 gzip JSON，兼容阶段一报告，只包含检查结果、生效配置和 trace 元数据，不附记忆或会话正文。宿主验证基线为 0.2.2-rc.5，范围 >=0.2.2-rc.5 <0.3.0-0。升级依据见 [宿主升级决策](decisions/0009-dsh-rc5.md)。

## 增长与整理

工作区的「整理」页独立于「设置」。新建整理会话与已有会话的打开、审阅和回滚分别操作；审阅与确认属于对应的记录。默认概况只显示笔记数及规则用量，其他指标按类别展开。切换回会话范围时返回笔记。

未应用的整理随 DSH 会话归档移出列表；「放弃整理」执行同一归档操作，不强制停止运行中的会话。归档期间不能提交、审阅或应用草稿，取消归档可找回，仍需通过快照校验。已应用或已回滚的记录保留，归档本身不回滚记忆。

`/stash health` 与「工作区概况」展示笔记总数、折叠状态、规则用量、长期未读、上次有效整理后新增、核实提交与 HEAD 不同及无法比较的数量。长期未读以最近一次完整的 `memory_view` 单篇读取时间为起点，没有读取记录时用首次观察到创建的时间。目录、半页、整理语料和离线读取不增加计数。`.stats.json` 的 v 为 1；创建与更新时间取自文件日志。索引从展开变为折叠时提示一次，保持折叠时不重复提示。

新建时选择的应用方式只授权这一个整理会话，与普通会话的「允许模型写入」开关无关。模式固定，不继承到下一次整理。整理会话只能访问自己的工作副本。每个会话保存 v3 清单和独立的 Markdown 基线与工作树；文件树按内容寻址，写入新版本后原子切换清单。模型用 `memory_view` 分页读取完整副本，用 `memory_write` 编辑正文、用 `stash_stage` 移动、合并、拆分或重置。中间状态可暂时存在待修正的规则导入。查看累计 `stash_diff` 不提交；读完最终差异后 `stash_submit` 才冻结审阅版本，或按本次授权自动应用。没有差异时不创建应用批次。返工沿用同一会话，第一次有效修改立即作废旧确认。已应用的整理不能再次提交。

提交检查正式基线、重定向、凭据、规则预算及快照版本。工作区变化后拒绝覆盖并保留副本。旧 v1/v2 草稿仅在基线一致时转换，v1 始终人工审阅，未知版本不覆盖。

一次整理组的文件记录以 `group`（整理会话 ID）、`op` 和必要时的 `redirect` 标记，别名从日志折叠派生。提交前检查快照、路径、凭据、规则预算与日志容量，先持久化 `.batch.json`，再逐条沿用 `.pending.json` 协议。读写请求恢复中断批次；离线 verify 只报告，不修复。回滚追加反向记录，保留原始字节、来源、无关编辑及审计历史。规则仍由 `externalRuleUpdates` 决定投递时机，纯索引变动不打断其他会话。

实现取舍与边界见[整理计划与回滚](decisions/0008-workspace-maintenance.md)。
