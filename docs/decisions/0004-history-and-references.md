# 阶段三：原始记录与引用

日期：2026-11-15。状态：已实现。宿主基线保持 0.2.2-rc.3。

## 与参考方案的取舍

- 沿用两个模型工具。memory_view 增加历史路径及 query、since、until、detail、all，未增加独立搜索工具，也未实现阶段四的会话记忆。
- 宿主 observeSession 的 all 模式恢复持久投影检查点，inspectSession 同步读取同一宿主对象的事件和轮次状态；冷会话不进入活动 session store。投影注册和缓存持久化由宿主管理。测试覆盖真实缓存文件、重建 Context、分叉继承和压缩后读取。
- 从宿主 extractSessionEventText 提取语义文本，在领域层做字面匹配。这样离线读取、在线读取、分叉去重和展示共享数据模型，不依赖全文索引，也不额外为每条匹配调用 readEvent。当前仍完整读取候选会话，时间窗不是 I/O 优化；结果明确报告实际扫描会话数。
- 复制按钮通过小型 Remote 端点查询消息所属轮次，没有要求客户端已加载整轮日志。完整事件范围、标题和时间来自宿主；不采用只复制轮次尾部事件的降级方案。时间显示为带 Z 的 UTC，避免链接文字缺失时区。
- 历史分页保留固定快照。按每次调用的当前日志重新算哈希会被本工具自己的结果不断打断，故采用每 agent 八个快照的有界续读表。重启后重读；没有新增持久正文副本。
- 离线工具不自行解析 DSH 工作区存储域，用已验证 workspace.json 的最后已知路径精确筛选 cwd。这是明确的离线限制；跨工作区完整引用仍可用。

## 扫描测量

2026-11-15 在 Windows、本地 C: 的 YMTC PC300-512GB-B NVMe SSD、Node.js 26.13.0 上运行：

    pnpm exec tsx packages/devtools/src/benchmark-history.ts

基准生成 28 个会话、2,800 轮、16,800 个事件，代表每天四个会话的一周合成负载；逻辑 JSON 共 29,796,228 字节，采用宿主默认 zstd 存储。每个会话有一次中文“架构”命中，执行完整工作区搜索。重建宿主后的首次观察耗时 356 ms，后续三次 351、330、337 ms。未清除操作系统磁盘缓存，因此这些数字不是物理磁盘冷读成绩；合成重复文本容易压缩，也不等同于真实一周生产负载。

本机可用磁盘均为 NVMe SSD，没有机械硬盘。HDD 测量未完成，不能据此推断 HDD 性能，也不把参考计划的双介质测量条件记为通过。基准接收输出目录参数，可在目标磁盘复测；生成日志及 measurement.json 保留于 .exclude，不入库。

当前样本不足以证明需要额外全文索引，阶段三保留字面扫描。1.0 前需补真实会话分布、大工具输出、物理冷缓存和 HDD 测量，再决定是否增加索引或流式扫描。

## 验证边界

自动测试覆盖带时区过滤、歧义引用、非法范围、中文子串、空白匹配、零结果与不可读区分、分叉去重、预算分页、缓存恢复、客户端链接与失败反馈、真实 SDK 粘贴引用后的读取、Web Gateway、tarball 安装和离线一致性。所有模型调用使用本地 mock。没有进行真实模型行为评估或 Desktop 人工视觉验收；Linux/macOS 以 CI 为准。
