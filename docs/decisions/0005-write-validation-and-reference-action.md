# 写入诊断与引用按钮

日期：2026-11-15。状态：已实现。

## 写入契约

人工测试发现 delete 传入 content: "" 后，通用 STASH_INVALID_DATA 提示错误地要求检查 edit 的唯一匹配。原校验正确拒绝了多余参数，但工具 schema 没有明确解释每种操作允许的字段，通用错误又掩盖了实际原因。

保留六种操作和严格省略规则。content 的空字符串对 replace 有实际含义，edit 的 new 空字符串表示删除片段；自动丢弃 delete 的 content 会隐藏调用方误解。DSH 的 write 是独立文件写入工具，content 为必填项；stash 的 memory_write 是操作分派接口。这种差异可能诱发误用，但一次实测不足以证明模型误用的原因。

当前宿主工具参数 schema 是受限的对象格式，不能直接表达根级判别联合。采用同一操作字段表生成 op 说明、领域输入联合类型和适配器校验规则，保持宿主兼容。模型可见错误通过有类型的原因在 core/templates 中渲染，只包含固定字段名、操作名和匹配数，不直接输出校验器或 YAML 解析器异常。

## 引用操作

使用 DSH 自带的会话引用图标，沿用现有操作栏尺寸、颜色和 Tooltip，避免普通文字按钮破坏工具栏风格。名称明确为“复制本轮引用”，说明其用途是定位原始记录。等待、成功和失败反馈留在固定按钮与浮层内，避免文字挤动相邻操作。

选用宿主 UI primitives 的源入口构建图标和 Tooltip；React 与 ReactDOM 由宿主提供。构建将 CSS 内联到宿主 classic script，安装与释放绑定插件作用域，避免产生浏览器无法执行的 ESM 样式导入。

## 验证

回归覆盖六种操作的字段约束、错误内容不回显、编辑与笔记错误不落盘、真实 SDK 误传后修正重试，以及按钮重复点击、剪贴板失败、成功恢复和卸载后的迟到响应。浏览器验收使用独立临时 DSH_HOME 和本地 mock，检查真实宿主的深浅主题、字号、悬停与键盘提示、复制和粘贴引用。
