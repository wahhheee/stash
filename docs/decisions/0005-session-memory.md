# 0005：会话提交与分支

日期：2026-11-16。状态：已实施。

阶段四保持 DSH 0.2.2-rc.3 依赖不变。实际接口核对以安装包和隔离测试为准，参考检出的仓库仅用于定位。

- 采用结果全文加前后哈希的提交，复用六种写操作和完整读取资格。相较记录操作片段，折叠不依赖未来编辑算法，成本是每次提交存储整个目标文件。没有另建会话记忆文件或与日志并行的私有正本。
- 原生成功结果使用 meta.stashCommit；PTC 使用 deferContext 的 stash-commit 消息。宿主当前也保留嵌套分派元数据，但不拿它提前确认外层尚未结算的写入。只折叠最终可持久化载体。重复裁剪事件按 UUID 和内容哈希链去重。
- PTC 同一根调用可连续读写；短暂覆盖层弥补 deferContext 晚于嵌套工具返回的时序。最终失败移除待提交项，外层结算和请求边界清除覆盖层。宿主日志仍是恢复后的唯一依据。
- 工作区与会话层分别应用现有预算，避免会话写入挤占既有工作区规则。索引仍延迟刷新；规则与写入确认严格按层处理，防止一次工作区写入顺便确认尚未展示的会话规则。
- 位置通知不确认规则或索引。分叉继承由日志前缀决定，与谱系展示无关。来源识别优先 stash 记录，其次切口事件指纹；多个匹配保留候选，不猜测直接父会话。
- 子代理父规则在请求边界读取。旁车只记录父会话 ID 与边界，避免把正文塞入诊断数据，代价是重放需要父日志。
- 会话清单用非空规则行数表示规则量，不尝试把自然语言拆成精确的“条”。当前笔记搜索按所属会话时间窗口筛选，并明确返回当前内容，不冒充某历史时刻的笔记。
- 提升采用两个现有工具完成读取与工作区 create，保留原笔记，提示 sources 指回完整引用；没有为阶段五预先新增界面或另一个工具。
- 实际 SDK 会话未自动附入工作区注册表；适配器现在在解析工作区时显式附入当前会话，使用宿主自己的 cwd 校验。

验证使用隔离 DSH_HOME 和本地 mock，覆盖原生/PTC 实际请求、分叉前缀、重启压缩、缓存删除重建、修改前版本冲突、未知版本与哈希错误、重复载体、子代理策略、跨会话参考和笔记提升。PTC 测试为每个 mock 工具调用生成唯一 ID，避免模拟器重启重复 ID 被宿主持久格式拒绝。SDK 未提供分叉端点，测试在宿主停止后使用其 SessionStore 分叉实现建立子会话，再通过 SDK 恢复。

尚未运行真实模型行为评估；Windows 以外由 CI 验证。没有发布 npm 或公开仓库。
